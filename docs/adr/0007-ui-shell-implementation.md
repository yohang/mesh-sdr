# ADR 0007: UI shell implementation

- Status: Accepted
- Date: 2026-10-06
- Deciders: project owner
- Epic: #450, part `epic/ui-1` (UI-008 #77, UI-001 #70, UI-009 #78, UI-003 #72, UI-005 #74, UI-004 #73). Builds on ADR 0003.

## Context

ADR 0003 fixed the app-shell architecture: boosted navigation that swaps `#main`, fragments on `HX-Request`, `light-dark()` tokens, a nonce-only CSP, islands, and axe-core in a CI-only container. Implementing it left some choices open. Several epics share the router (auth-1 adds middlewares, grid-2 adds routes). There is no settings store yet (ADM-002). Icons are needed without Node or image tools. The axe job had to be designed.

## Decision

### Package boundaries and router hook

- **`internal/http`** owns the cross-cutting HTTP layer: the router, the request id, logging and recovery middlewares, the security headers (`security.go`) and the server.
  - Modules plug in through `Module { Middlewares(); Routes(chi.Router) }`, called as `NewRouter(logger, api, modules...)`.
  - Module middlewares wrap every route, API included, in module order, after the router's own middlewares (security headers included) and before any route.
- **`internal/web`** holds the shared presentation, with no domain logic:
  - `layout`: the document, `#main` and the error page;
  - `render`: the render helper;
  - `static`: tokens CSS, ES modules and generated icons;
  - `icongen`: the icon generator.
- **`internal/shell`** is the UI module, layered like any other module (`domain`, `app`, `infra`, `http`, `wire.go`).
  - It builds the per-request shell data (`render.ShellSource`): site name, theme and footer links.
  - It serves `/`, `/policy`, `/robots.txt`, `/manifest.webmanifest` and `/favicon.ico`.
  - It owns the HTML 404 and 405 pages of every non-API path.
- `shell.Wire` exposes the `render.Renderer`. Every module with HTML pages (auth's login page, for example) receives it by constructor injection and never renders the layout itself.

### Render helper semantics

`Renderer.Page(w, r, status, page, content, fragment)` returns the fragment only when all of these hold:

- `HX-Request: true`;
- `HX-Boosted` is absent;
- `HX-History-Restore-Request` is absent;
- `HX-Request-Type` is not `full`.

Otherwise it returns the full page. A `nil` fragment means the page has no fragment representation.

Every HTML response from the helper:

- sends `Vary: HX-Request, HX-Boosted, HX-Request-Type, HX-History-Restore-Request` and `Cache-Control: no-store`, because pages depend on the session, role and theme;
- is rendered into a buffer first, so a template error becomes a clean 500.

`Renderer.Error(w, r, status)` follows the same rule for 403/404/405/5xx, because htmx 4 swaps error responses into the request's target:

- for a full-page request (plain, boosted or history restore), it renders the error page inside the shell, which then lands in `#main`;
- for a fragment request, it renders only the error content (heading, message, link home) into the request's target. It sends no `HX-Retarget`, so an error replaces the part that failed, not the page. A panic still gets chi's plain 500 from the recoverer. An HTML panic page is left for later.

### Theme mode: interim source

- `settings.ui.theme_mode` (`light` | `dark` | `auto`, default `auto`) is the first key of the hub's `[settings]` table. TECHNICAL_SPEC §7.4 defines `[settings]` as the lockable namespace.
- The key can be set in `hub.toml` or with `MESHSDR_SETTINGS__UI__THEME_MODE`.
- Config validates the value at load, and the JSON Schema marks `settings.*` keys `lockable: true`.
- `shell/app` reads it through the `Settings` port. The interim adapter `shell/infra.ConfigSettings` returns the config value, or the default when none is set. A failing source or invalid value falls back to `auto` and logs a Warn.
- ADM-002 replaces the adapter with the precedence config (locked) > DB > default, without touching `app` or `http`.
- The usage policy follows the same pattern with `settings.receiver.usage_policy_text`:
  - Markdown, at most 20000 characters; unset means the built-in neutral default in `shell/app/default_policy.md`.
  - Rendered with `github.com/yuin/goldmark` (owner-approved dependency) using its defaults, which drop raw HTML and dangerous URLs. There is no sanitizer.
  - Headings are shifted so the page owns the `h1`.

UI-001 stays open: its admin rights (edit as admin only) need ADM-002 and AUTH.

### Icons

- Icons are generated by `go:generate` (`internal/web/icongen`) using `golang.org/x/image/vector`. One placeholder geometry (three mesh nodes on an accent tile) produces all of them:
  - `icon.svg`;
  - `icon-192.png` and `icon-512.png`;
  - `icon-maskable-512.png`, with the mark inside the safe zone;
  - `apple-touch-icon.png` (180 px);
  - `favicon.ico`, which holds 16/32/48 px PNG images.
- The output (`internal/web/static/icons/`) is generated and never committed. Replacing the artwork means changing the geometry and colors in `icongen`.
- The manifest is served dynamically because its colors follow the theme mode: in `auto` it uses the light color. The document also sends media-qualified `theme-color` metas.
- There is no service worker.

### Accessibility CI job

- **Location.** `.infra/a11y/` contains:
  - a `Dockerfile` based on `mcr.microsoft.com/playwright` (pinned tag and digest);
  - `package.json` and `package-lock.json` (`playwright`, `@axe-core/playwright`, exact versions);
  - `run.mjs`, `urls.txt` and `compose.yaml`.
- **How it runs.** The compose file builds the hub's production image and migrates a fresh volume. It then starts three hubs on that database, one per theme mode (`auto`, `light`, `dark`, set with `MESHSDR_SETTINGS__UI__THEME_MODE`), and runs the checker. The CI job `a11y` (after `check`, 20-minute timeout) and `make a11y` use it, and always tear the stack down.
- **What it checks.**
  - Each `urls.txt` entry gets its expected status and axe-core with tags `wcag2a`, `wcag2aa`, `wcag21a` and `wcag21aa`.
  - Every entry runs for each theme mode, in the light and dark OS color schemes, at 390×844 and 1280×800.
  - The theme is applied: `data-theme` is the mode, and the page background is the token set the mode selects (a forced mode ignores the OS scheme).
  - One boosted navigation is checked: the document stays the same, focus lands on `#main`, the new page is announced and the title changes.
  - These fail the run: any CSP or Permissions-Policy console message, page error, failed request, or subresource answering 400 or more.
- **Contract with features.** Feature tickets add their pages to `urls.txt`. Authenticated pages will need a login fixture once AUTH lands.
- **Contrast in Go.** `web.TestTokenContrast` parses the `light-dark()` color tokens and enforces 4.5:1 for text and 3:1 for UI parts in both sets.
- **Template rules.** `web.TestTemplateRules` enforces the template rules of ADR 0003.

## Consequences

- auth-1 and grid-2 plug in through `Module`, and HTML pages use the shell `Renderer`. `internal/http/server.go` needs no further edits for new routes.
- The settings store must keep the `Settings` and `PolicySettings` ports, and the `settings.*` keys and their origins.
- Generated icons join the other generated files (`.gitignore`, `.dockerignore`, `make clean`).
- New Go dependencies: `github.com/yuin/goldmark` and `golang.org/x/image` (the generator only).
- Node exists only in the `.infra/a11y` image.
